## 1. Script bloat: business logic in pipeline scripts

**Severity**: High
**Location**: `scripts/run_alpha_v1_daily.py` (1339 lines, ~30 functions)
**Files**: `scripts/run_alpha_v1_daily.py`, `scripts/run_alpha_v1_shadow_observation.py`, `scripts/ops/check_shadow_status.py`

The daily ops script contains substantial business logic that belongs in the `qsys.ops` package:
- MTM snapshot construction (`_try_mark_to_market`, 159 lines)
- Post-close reconciliation (`run_postclose`, 246 lines)
- Pre-open orchestration (`run_preopen`, 92 lines)
- Execution commit (`_commit_execution`, 78 lines)
- Notification message building (`_build_preopen_message`, 60 lines; `_build_postclose_message`, 83 lines)
- Stale price checking (`_check_stale_prices`, 95 lines)
- Model loading & prediction (`load_model_and_params`, `generate_predictions_for_date`)

**Recommendation**: Extract low-risk helpers to `qsys/ops/` submodules (commit_guard, daily_artifacts, mtm, replay). Keep high-risk orchestration (preopen/postclose control flow, rebalance decision) in script.

**Boundary violated**: ADR-005 spirit (Protected Core doesn't name script/ops boundary explicitly, but script complexity creates maintenance risk).

## 2. Shadow CSV/JSON dual-write: ledger bypass

**Severity**: High
**Location**: `qsys/ops/shadow_rebalance.py` (lines 485-505), `scripts/run_alpha_v1_daily.py` (lines 908-909)

The shadow rebalance module writes to `shadow/account.json` and `shadow/positions.csv` after every execution, even though the SQLite ledger (`trade.db`) is the designated source of truth (ADR-005). This dual-write creates a drift risk: if one write succeeds and the other fails, the two sources diverge.

`run_alpha_v1_daily.py` also copies ledger rows back to shadow CSV/JSON:
```python
shutil.copy2(..., "shadow/account.json")
shutil.copy2(..., "shadow/positions.csv")
```

**Recommendation**: Remove shadow file writes from production path. Keep reads only as fallback (see finding 5). The SQLite ledger is the SOT; shadow files are legacy.

**Boundary violated**: ADR-005 (shadow files are not Protected Core, but dual-write creates data integrity risk at the ledger boundary).

## 3. Artifact outputs lack ADR-007 compliance

**Severity**: Medium
**Location**: All artifact outputs in `experiments/alpha_v1_daily/`

Current artifact columns compared to ADR-007 required fields:

| Artifact | ADR-007 Required Fields | Current Status |
|----------|------------------------|----------------|
| SignalArtifact (predictions CSV) | 14 required fields | 5 present: trade_date, instrument, score. **Missing**: candidate_id, model_version, signal_version, data_cutoff, rank, raw_prediction, normalized_score, target_weight_raw, created_at, config_hash, feature_schema_version |
| OrderIntentArtifact (order_intents.csv) | 12 required fields | 9 present: trade_date, instrument, side, target_weight, etc. **Missing**: strategy_id, order_id, order_type, price_band |
| ExecutionArtifact (ledger_rows.csv) | 11 required fields | 8 present. **Missing**: execution_id, order_id, fee_asset, constraint_info |
| PortfolioSnapshot | 10 required fields | Not written as a structured artifact |

**Recommendation**: Implement ADR-007 sidecar writers that produce standard artifacts alongside existing outputs. Do not change existing artifact format; add `*-adr7.json` sidecars.

**Boundary violated**: ADR-007.

## 4. Private function imports across module boundary

**Severity**: Medium
**Location**: `scripts/run_alpha_v1_daily.py` (lines 940, 1195)

The daily ops script imports private functions from `qsys.ops.shadow_rebalance`:
```python
from qsys.ops.shadow_rebalance import _fetch_market_snapshot      # line 940
from qsys.ops.shadow_rebalance import _write_execution_to_ledger   # line 1195
```

Private (`_`-prefixed) functions are internal implementation details. Importing them from outside the module creates tight coupling and breaks encapsulation.

**Recommendation**: Either (a) make these functions public and document them as part of the module's API, or (b) inline or relocate the logic.

**Boundary violated**: Python module encapsulation convention.

## 5. Fallback read from shadow/account.json

**Severity**: Low
**Location**: `scripts/run_alpha_v1_daily.py` (lines 113-120)

`_should_rebalance()` tries the ledger first, then falls back to `shadow/account.json`:
```python
# Try ledger first, fall back to shadow/account.json
last_trade_date: str | None = None
if Path(LEDGER_DB_PATH).exists():
    try:
        service = LedgerService(LEDGER_DB_PATH)
        last_trade_date = service.get_latest_trade_date(...)
    except Exception:
        pass
if not last_trade_date:
    account_path = PROJECT_ROOT / "shadow" / "account.json"
    ...
```

This is reasonable for backward compatibility but should be removed once ledger migration is fully complete.

**Recommendation**: Remove after confirming all environments have migrated to SQLite ledger. Track with a TODO comment.

**Boundary violated**: Minor — ledger should be sole SOT.

## 6. Database access fragmentation (meta.db)

**Severity**: Low
**Location**: `qsys/backtest.py`, `qsys/ops/data_coverage.py`, `qsys/feature/groups/industry_context.py`

Several modules open `meta.db` directly via `sqlite3.connect()`. These access metadata, not trading state, so they don't violate the ledger boundary. However, the pattern is inconsistent — some modules go through abstractions, others connect directly.

**Recommendation**: Accept as-is. Meta.db is a different concern from the trading ledger. Document in ADR-005 that meta.db is not in Protected Core scope.

**Boundary violated**: None (out of scope).

---

## 7. alpha_v1 role mixing in single script

**Severity**: Low
**Location**: `scripts/run_alpha_v1_daily.py`

The script runs three distinct modes (`--mode preopen | postclose | train`) with shared module-level state (MODEL_DIR, PREDICTIONS_DIR, etc.). Mode selection is at the argparser level. The modes share helper functions but have independent entry points.

This is a pragmatic design for a personal quant system. Full separation (one script per mode) would add ceremony without clear benefit.

**Recommendation**: Accept as-is. Document that this is a design choice, not an oversight.

**Boundary violated**: ADR-006 (mixing preopen/postclose/train under one script blurs lifecycle stages, but the `--mode` flag provides sufficient separation).
